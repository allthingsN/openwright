# `openwrightcore` — Go evidence core (Option C)

A Go reimplementation of the OpenWright evidence core: canonical JSON (RFC 8785 /
JCS subset), RFC 6962 Merkle hashing, and Ed25519 checkpoint signing. This is
Option C from [../docs/OTEL_PROCESSOR_SCOPE.md](../docs/OTEL_PROCESSOR_SCOPE.md):
it enables a future **Python-free, single-binary** deployment (e.g. a native Go
Collector component that produces evidence in-process).

> **Why this is gated.** A second implementation of the cryptographic core is a
> direct risk to the trust model — if Go and Python disagree by one byte,
> evidence from one fails verification by the other. So this package ships
> **with** the gate that protects against drift, not before it.

## What's here

```
core-go/
  canonical.go        canonical JSON, byte-identical to Python's canonical_bytes
  merkle.go           RFC 6962 leaf/node/root + inclusion proofs
  consistency.go      RFC 9162 consistency proof generator + verifier
  timestamp.go        to_rfc3339 integer normalization (exact-integer, no float)
  event.go            full ComplianceEvent leaf-content serialization
  checkpoint.go       checkpoint signing bytes + Ed25519 sign/verify
  report.go           full signed-report assembly + signing + root recomputation
  conformance_test.go reproduces conformance/vectors.json byte-for-byte (5 categories)
  cmd/openwright-core/  CLI used by the cross-language interop check
  verify_interop.py   Python<->Go Ed25519 interop (checkpoint + full report, both directions)
```

## The two-layer guarantee

1. **Byte-identity (the gate).** `conformance/vectors.json` is generated by the
   Python core (`conformance/generate_vectors.py`, the single source of truth)
   and covers canonical-encoding edge cases (`\b`/`\f` escapes, control chars,
   unicode, no HTML escaping, null-dropping, key sorting) plus Merkle roots and
   inclusion proofs. Both languages must reproduce it:

   ```bash
   go test ./...                                   # Go reproduces the vectors
   poetry run pytest tests/test_conformance.py     # Python stays the source of truth (CI, no Go)
   ```

2. **Interop.** Evidence produced by either core verifies under the other —
   both a signed *checkpoint* and a full signed *report*:

   ```bash
   poetry run python core-go/verify_interop.py
   # Checkpoint interop:
   #   OK   Direction 1 — Python verifier validated Go-signed checkpoint
   #   OK   Direction 2 — Go verifier validated Python-signed checkpoint
   # Full-report interop:
   #   OK   Direction 1 — Python verify_report() validated Go-emitted report
   #   OK   Direction 2 — Go recomputed root + verified checkpoint of Python report
   ```

   The Go binary `emit-report`s a full report (events + signed checkpoint over
   the Merkle root + per-event `leaf_hash` + inclusion proofs + report signature
   + embedded SubjectPublicKeyInfo PEM) that `openwright.verify.verify_report`
   accepts; and `verify-report` recomputes the root from a Python report's events
   (through the same event-model serializer) and verifies its checkpoint.

## Status — complete, conformance-gated evidence core

**Option C is now a complete, conformance-gated evidence core.** It reproduces the
Python core's evidence primitives byte-for-byte and produces evidence the Python
verifier accepts:

- **Canonical JSON** (RFC 8785 / JCS subset) — byte-identical to `canonical_bytes`.
- **Merkle** — RFC 6962 leaf/node/root + inclusion proofs, **and** RFC 9162
  consistency proofs (generator + verifier).
- **Timestamps** — `ToRFC3339` integer normalization (the seconds-vs-nanoseconds
  heuristic, exact-integer math with no float, fixed 9-digit fraction + `Z`).
- **Full event-model serialization** — the `ComplianceEvent` leaf content
  (`exclude_none`; the always-kept empty `provenance`/`attributes`/`labels` dicts;
  enums as their string value; nested attributes with ints preserved; unicode
  preserved; unknown top-level fields round-tripped).
- **Signed checkpoints** and a **full signed report** (`emit-report`): events +
  signed checkpoint over the Merkle root + per-event `leaf_hash` + inclusion proofs
  + a report signature + embedded SubjectPublicKeyInfo PEM, in the shape
  `report.py:build_report` produces.

> **It is a Go core, not a second source of truth.** The Python core remains the
> single source of truth for the vectors; Go's job is to produce evidence
> *byte-identical* to Python and verifiable by the Python verifier. A single byte
> of divergence breaks cross-language verification, which is exactly why the gate
> below is non-negotiable.

The conformance gate (`conformance_test.go`) now strictly checks **all five**
vector categories — `canonical`, `merkle` (root + inclusion), `consistency`,
`timestamps`, and `events` — and fails the build on any divergence. The three
things that previously had to land before C could produce evidence are **DONE**:

- **Timestamp normalization.** ✅ `timestamp.go` (`ToRFC3339`) reproduces the
  `timestamps` vectors exactly (exact-integer, no float — F5).
- **Consistency proofs.** ✅ `consistency.go` implements both the proof generator
  and the RFC 9162 verifier; the gate reproduces every committed proof's bytes
  *and* verifies it (and rejects a tampered one).
- **Full event-model serialization.** ✅ `event.go` mirrors the pydantic
  `ComplianceEvent` → dict serialization; the gate unmarshals each `events` vector
  and asserts the re-serialized canonical bytes and leaf hash match — so a missing
  struct field (a silently dropped key) fails the test.
